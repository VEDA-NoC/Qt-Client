# 02. 이벤트·심각도·상태 정책

- 상태: 부분 확정 (센서 임계값·외부 차량 분류 연계 대기)

## 공통 상태 모델

이벤트의 발생 상태와 운영자의 확인 상태를 분리한다.

| 필드 | 값 | 의미 |
|---|---|---|
| `condition_state` | `ACTIVE`, `CLEARED` | 원인이 현재 유지되는지 여부 |
| `ack_state` | `NOT_REQUIRED`, `UNACKED`, `ACKED` | 확인 불필요 또는 운영자가 확인했는지 여부 |
| `resolution_state` | `OPEN`, `RESOLVED` | 후속 조치까지 종료했는지 여부 |

`ACKED`는 경보를 보았다는 의미일 뿐 원인이 해제됐다는 의미가 아니다. `CRITICAL` 이벤트는 원인 해제 후에도 운영자가 결과를 기록해야 `RESOLVED`로 변경한다.

## 심각도

| 수준 | UI 색상 | 알림 방식 | 확인 필요 |
|---|---|---|---|
| `INFO` | 정보색 | 이벤트 목록 기록 | 기본적으로 불필요 |
| `WARNING` | 주황/황색 | 배지·알림음 선택 | 필요 |
| `CRITICAL` | 적색 | 고정 배너·반복 알림음 | 필수 |

## 업무 이벤트 제안

| 이벤트 | 기본 심각도 | 발생 조건 | 자동 해제 조건 | 확인·처리 규칙 |
|---|---|---|---|---|
| 주정차 시작 | INFO | 차량 점유가 안정 판정 시간 이상 유지 | 차량 출차 | 기록만 수행 |
| 12시간 주정차 위반 | WARNING | 같은 차량/점유 상태가 12시간 초과 | 출차 또는 관리자 예외 처리 | 운영자 확인 필요 |
| 충전 완료 | INFO | 충전기가 완료 상태 보고 | 차량 출차 또는 새 충전 세션 시작 | 선택적 확인 |
| 화재 가능성 | WARNING | (가능하다면)카메라, 주정차 정보, 온도 등 화재 후보 조건 충족 | 정상 범위가 유지 시간 이상 지속 또는 오탐 처리 | 운영자 확인, 방재판 단계 진입 가능 |
| 화재 대응 필요 | CRITICAL | 복수 센서 확인 또는 확정 임계값 초과 | 센서 정상화만으로 자동 종료하지 않음 | 확인, 방재 단계 실행, 결과 기록 후 수동 해결 |
| 장치 장애 | WARNING 또는 CRITICAL | heartbeat 누락, 센서 범위 오류, 통신 오류 | 연속 정상 heartbeat N회 | 중요 장치는 확인 필수 |
| 비전기차 충전구역 점유 | WARNING | 구역 점유 차량을 `NON_EV_CONFIRMED`로 판정 | 출차 또는 관리자 예외 처리 | 운영자 확인 필요 |
| 차량 분류 실패 | WARNING | 번호판 미인식 또는 외부 조회 실패 상태가 유지 | 재인식 성공, 출차 또는 운영자 처리 | 전기차로 임의 허용하지 않음 |

## 추가 운영 이벤트 제안

| 이벤트 | 심각도 | 해제 조건 |
|---|---|---|
| CCTV 오프라인 | WARNING | 스트림 및 heartbeat 정상 복귀 |
| 녹화 실패 | CRITICAL | 새 세그먼트 저장과 무결성 확인 성공 |
| 저장공간 부족 | WARNING | 사용률이 경고 해제 임계값 아래로 감소 |
| 저장공간 가득 참/읽기 전용 | CRITICAL | 기록 가능한 상태 복구 |
| 시간 동기화 이상 | WARNING | 오차가 허용 범위 안으로 복귀 |
| 제어 명령 실패 | CRITICAL | 원인 확인 후 수동 해결 |
| 서버 과열 | WARNING 또는 CRITICAL | 온도가 해제 임계값 아래에서 일정 시간 유지 |

## 경보 폭주 방지

- 동일한 `source_id + event_type`은 활성 상태에서 중복 생성하지 않고 카운트와 최근 시각을 갱신한다.
- 발생 임계값과 해제 임계값에 hysteresis를 둔다.
- 장치 장애가 상위 원인일 때 하위 센서 장애를 한 그룹으로 묶는다.
- 화재 경보는 억제하지 않되 동일 원인의 알림음 반복 주기는 제한한다.

## 미결정

- 화재 가능성과 화재 대응 필요를 구분하는 센서 조합 및 임계값 / STM에서 결정
- 차량 동일성 판정에는 번호판을 사용한다. 카메라 앱의 LPR을 우선하고 미지원 시 별도 인식 경로를 검토한다.
- 12시간 기준의 예외 차량과 운영자 연장 처리 방식 / 기능 구현 이후 고려
- 충전 완료 이벤트 데이터 출처와 충전기 프로토콜 / STM과 통신
