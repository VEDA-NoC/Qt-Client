# 08. UI·브랜드·상용화 고려사항

- 상태: 확정 (시각 QA 대기)

## UI 방향

- `.ref/ui/concepts-v1/`의 전체 배치를 기준으로 한다.
- 좌측 사이드바는 `2.png`의 짙은 Navy 배경, 아이콘+텍스트, Orange 선택 표시 방식을 기준으로 한다.
- 기준 해상도는 1920x1080, 최소 논리 해상도는 1280x720이며 Windows 배율 100/125/150%를 검증한다.
- 실시간·녹화·이벤트·장치 및 제어·설정의 5개 최상위 메뉴를 사용한다.
- 계정 관리는 설정 하위로, 센서는 STM32 상세 하위로 이동한다.
- 다크 모드는 당장 제공하지 않지만 모든 색을 semantic token으로 분리한다.

## 글꼴

브랜드 가이드는 Hanwha Gothic을 제시하지만 배포 파일과 상용 앱 포함 라이선스가 현재 자료에 없다. 제품 UI 기본 글꼴은 `Pretendard`를 권장한다.

- 한글·영문·숫자 가독성이 좋고 SIL Open Font License 1.1로 상용 앱 번들링이 가능하다.
- `Regular`, `Medium`, `SemiBold`, `Bold` 정적 폰트 파일을 앱 리소스에 포함하는 방식을 우선한다.
- 배포물에 Pretendard 저작권 고지와 OFL 전문을 포함한다.
- fallback은 `Segoe UI`, `Malgun Gothic`, `sans-serif` 순서로 둔다.

## 상용 프로그램 화면

`설정 > 정보 및 법적 고지`에 다음 항목을 제공한다.

- 제품명, 버전, build 번호, 제조·공급 주체, 저작권
- 최종 사용자 라이선스 및 제3자 오픈소스 라이선스
- Pretendard 등 번들 글꼴 라이선스
- 개인정보 처리방침과 영상정보처리기기 운영·관리 방침 링크
- 보안 취약점 신고 연락처와 기술지원 정보
- 브랜드·상표 사용 고지
- 업데이트 서명과 현재 인증서 정보 요약

화면의 핵심 고지는 외부 문서 링크만으로 대체하지 않는다. 짧은 개인정보 처리
요약과 필수 고지값은 항상 표시하고, 길고 자주 보지 않는
`영상정보처리기기 운영 상세`만 disclosure 형태로 접을 수 있게 한다. disclosure는
작은 동작 버튼 대신 전체 너비 section row와 우측 chevron을 사용한다.

제품명과 버전은 화면 아래에 항상 표시한다. Pretendard 고지는 주요 개인정보
본문에 단독 항목으로 두지 않고 Qt·FFmpeg 등과 함께 `오픈소스·제3자 라이선스`로
묶는다. 정책과 공식 출처 링크는 화면에서 항상 접근할 수 있어야 한다.

## 개인정보·영상 보안 설계

- 차량번호와 개인을 식별할 수 있는 CCTV 영상은 개인정보로 취급할 가능성이 높으므로 최소 수집, 목적 제한, 보존 기간과 접근 통제를 설계한다.
- 영상 조회·검색·재생·내보내기·삭제·권한 변경 이력을 감사 로그로 남긴다.
- 내보낸 영상에는 사용자, 시각, 사건 ID 워터마크와 무결성 해시를 선택적으로 포함한다.
- 권한이 없는 사용자의 차량번호 마스킹과 영상 privacy mask를 검토한다.
- 저장 영상과 DB의 암호화 여부, 키 저장 위치, 백업·폐기 절차를 출시 전에 위협 모델로 확정한다.
- TLS 인증서 검증을 끌 수 있는 상용 옵션을 제공하지 않는다. 초기 장치 등록 시 인증서 fingerprint 확인 절차를 둔다.
- 로그에 비밀번호, token, 전체 차량번호, 개인 영상 경로를 불필요하게 남기지 않는다.

### 차량번호와 위반 evidence 보존 정책

- 이벤트 목록에서는 번호판을 기본 마스킹한다. 예: `12가****`.
- 전체 번호판은 권한 있는 상세 화면에서만 일시 표시하고 조회자·시각·목적을 감사
  로그에 남긴다.
- 정상 주차는 Pi DB/HDD에 raw 번호판이나 evidence crop을 별도로 보존하지 않는다.
- camera+STM으로 확정된 EV 전용면 위반만 raw 번호판, evidence crop 또는 녹화 참조를
  최대 30일 보존한 뒤 자동 파기한다.
- 이의제기 건은 별도 legal hold와 해제 시점을 기록한다.
- 동일 차량 correlation은 plain hash가 아닌 secret-key HMAC token을 사용한다.
- 기존 녹화 영상의 retention과 열람 권한에도 같은 정책을 적용한다.
- 이벤트 ack, 원문 번호판 열람, 방재 실행 승인은 서로 다른 권한으로 관리한다.

### 운영 정보 제공 경계

처리 목적·항목·보유기간·전체 번호 열람 조건과 영상정보처리기기의 설치 목적·장소,
촬영 범위·시간, 운영 주체, 관리책임자 연락처, 열람·삭제 문의 경로를 표시한다.
운영 주체·연락처·실제 보존기간은 Qt source에 하드코딩하지 않고 Pi policy/config
API에서 받는다. 필수 값이 비어 있으면 관리자에게 `법적 고지 설정 미완료` 경고를
표시하되 일반 사용자에게 내부 endpoint, filesystem, 보안 구현 세부는 노출하지
않는다. 정책 버전·시행일·마지막 갱신일과 법령·개인정보위 출처 링크도 함께 표시한다.

개인정보 관련 내용은 제품 설계 초안이며 법률 자문을 대신하지 않는다. 실제 설치 장소와 운영 주체에 따라 안내판, 운영·관리 방침, 열람·삭제 요구 처리, 제3자 제공 기록 등을 확정해야 한다.
