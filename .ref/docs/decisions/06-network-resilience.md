# 06. 네트워크 장애 대응

- 상태: 확정

## 연결별 정책

| 대상 | 감지 | 재연결 | 복구 동작 |
|---|---|---|---|
| RTSPS 실시간 | read timeout, RTSP 오류 | 1, 2, 4, 8, 15, 30초 상한 + jitter | 마지막 프레임에 연결 끊김 시각 표시, 성공 시 자동 재생 |
| RTSPS VOD | read/seek 오류 | 자동 반복보다 세션 상태 재조회 | 현재 시각 유지 후 재개 또는 명시적 실패 표시 |
| Qt-Pi TLS | 5초 heartbeat | 지수 backoff | 마지막 event sequence 이후 이벤트 재조회 |
| Pi-STM32 | heartbeat/프레임 timeout | 통신 재시도 후 장치 장애 생성 | 센서 snapshot과 마지막 명령 상태 재동기화 |

## 이벤트 복구

- 서버는 증가하는 `event_sequence`를 부여한다.
- Qt는 마지막으로 반영한 sequence를 보관하고 재접속 시 그 이후 데이터를 요청한다.
- 오래된 sequence가 보존 범위를 벗어나면 시간 범위 snapshot으로 다시 동기화한다.
- 같은 `event_id`는 여러 번 수신해도 한 번만 반영한다.

## 명령 복구

- 응답 유실 시 동일 `command_id`의 상태를 조회한다.
- 위험 명령은 새 ID로 자동 재전송하지 않는다.
- UI는 `서버 접수`, `장치 접수`, `실행 완료`를 구분한다.
- Qt 종료 후에도 서버 감사 로그와 최종 상태가 남아야 한다.

## 서버·저장장치 장애

- 디스크 쓰기 실패 시 녹화를 중단하고 즉시 CRITICAL 이벤트를 생성한다.
- SQLite와 영상 파일 작성 순서 및 재부팅 후 orphan 파일 복구 절차를 정의한다.
- DB 손상 대비 백업·WAL·무결성 검사 정책을 별도 구현 단계에서 확정한다.
- 저장공간 자동 삭제는 가장 오래된 보호되지 않은 세그먼트부터 수행한다.

## UI 상태

- `연결 중`, `재연결 중`, `인증 실패`, `서버 오프라인`, `카메라 오프라인`, `녹화 없음`, `녹화 실패`를 서로 다른 상태로 표시한다.
- 마지막 프레임을 정상 영상처럼 보이지 않도록 dim 처리하고 끊김 시각을 겹쳐 표시한다.
- 사용자 작업이 필요한 오류와 자동 복구 중인 경고를 구분한다.
